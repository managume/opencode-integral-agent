Prepare Integral to work in the active project. This command is optional; ordinary natural-language requests must work without running it first.

Inspect the active location, repository root, project purpose, instructions, manifests, existing plans, Git state, `.opencode/LEARN.md`, and `.opencode/checkpoints/`. Reuse valid setup and verified state. Do not scan unrelated home directories or other projects.

For an existing project, identify its technologies, current state, applicable constraints, and only the setup gaps that would block work. Preserve existing files and settings. Do not create a duplicate plan, memory, model table, or feature map.

For a new or empty project, ask for its goal and material constraints if they cannot be inferred. Do not invent requirements or a technology stack. Once clear, prepare only the useful basics: concise project instructions, a minimal plan, safe `.gitignore` entries, and missing LEARN memories. Do not create application code, install dependencies, add remotes, or publish changes. Initialize local Git only when the user explicitly requests it or the project setup already authorizes that action.

Use existing model assignments when valid. Do not run external model research, change the user's model settings, or require a separate model command. Start or resume ordinary development even if this preparation command was not run.

Finish with a brief status summary: what was already ready, what was safely initialized, any incompatibility or blocker, and the next useful action. Do not report a setup item as complete without verifying it.
